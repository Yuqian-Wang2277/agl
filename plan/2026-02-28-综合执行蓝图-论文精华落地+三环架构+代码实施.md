## 零、项目的核心难点与最终目标（先看这里）

### 0.1 这个项目到底想做什么

用一句话描述：**训练一个 LLM，让它能够从几道"例题+解法"中，自动归纳出可迁移的解题策略，并把这个策略成功应用到没见过的新题上。**

```
输入（训练时）：
  [例题1: 问题 + 答案]
  [例题2: 问题 + 答案]  ← 这些叫 few-shot examples，同一类题型
  [例题3: 问题 + 答案]
        ↓
[模型被训练来做这件事] → 输出一段"策略文本"
        ↓
把这段策略文本给另一个模型，让它解一道新题
→ 如果新题答对了，说明策略提取得好
→ 把"是否答对"作为信号训练前面的策略提取模型
```

最终效果：模型看到新类型的问题（没训练过的题型），能从几道示例中快速总结出通用解法，举一反三。

### 0.2 项目的核心难点

**难点 1：奖励信号不可靠（最严重）**

策略的好坏很难直接测量。现在用一个 Scorer LLM（Qwen3-8B）来打分，但这个 Scorer 本身可能和"策略是否真正有效"脱节——Scorer 打高分不等于用这个策略能答对题。这叫 **reward hacking**（奖励黑洞）：模型学会写出让 Scorer 满意的策略，而不是真正有用的策略。

**难点 2：策略质量无法用程序验证**

当前策略是一段自由文本（只要有 `<strategy>` 标签即可），无法被程序解析为"步骤 1、步骤 2..."。这导致：
- 无法判断策略是否真的有逻辑步骤
- 无法计算"策略覆盖了问题的哪些关键点"
- 无法区分"废话策略"和"有效策略"

**难点 3：没有"由易到难"的训练节奏**

所有题型被同等对待，但有些题类型模型已经很擅长（学不到新东西），有些题类型模型完全不会（也学不到新东西）。最有价值的是"刚好在能力边界上的题"（对了一半、错了一半的那种），但当前没有任何机制去优先训练这类题。

**难点 4：好策略和坏策略没有对比**

训练数据只有"生成策略 → 打分"，没有"好策略 vs 坏策略"的显式对比。模型不知道"这样写比那样写好在哪里"，只能靠 Scorer 的分数盲目摸索。

**难点 5：跨域迁移（OOD）验证未闭环**

项目的终极目标之一是能迁移到没见过的题型，但 Stage1（策略提取训练）目前对"是否能迁移"毫无感知，Stage2（策略应用评估）有跨域测试但没有把结果反馈回 Stage1 的训练。

### 0.3 最终呈现效果应该是什么

**系统交付物（完整系统运行时的样子）**：

```
用户给 3~5 道同类型题（例题+解法）
         ↓
系统自动提取结构化解题策略：
  TYPE: 速率比较型问题
  STEPS:
    1. 识别题目中涉及的两个量（速率A、速率B）
    2. 设定公式 R = A/B，确定比较方向
    3. 代入数值计算比值
  CHECK:
    - 确认比值 > 1 表示A更快，< 1 表示B更快
         ↓
把上述策略交给答题模型，解一道同类型的新题
→ 答对率 > 基线（不用策略直接答）提升 10~18%
→ 对没见过的题型（OOD），策略迁移后仍有 5~10% 提升
```

**论文层面的呈现**（如果发论文）：
- Ablation Table 展示：格式升级、混合奖励、RSFT、课程学习各自的贡献
- 主要指标：ID correctness、OOD correctness、grounded proxy
- 核心创新：可验证的半结构化奖励（grounded proxy）+ 方差校准课程

## 一、什么是 Grounded Proxy（接地奖励代理）

> 这是本项目最核心的技术概念，读懂这个才能理解所有优化方向。

### 1.1 为什么需要 Grounded Proxy

当前系统用 **Scorer LLM** 来评估策略质量，给出 0~1 的分数。但这有一个根本问题：

```
Scorer 打 0.9 分 ≠ 这个策略真的能帮答对题
Scorer 打 0.3 分 ≠ 这个策略就没用
```

Scorer 是另一个 LLM，它打分基于自己的"判断"，而这个判断可能和实际答题效果完全脱节。这就是为什么把 `correctness_weight` 设为 0 是危险的——我们用了一个主观打分取代了客观结果。

**Grounded**（"接地"）的意思是：把奖励信号锚定在可以客观测量的东西上，而不是另一个 LLM 的主观意见。

### 1.2 Grounded Proxy 的具体含义（最终版）

> **背景说明**：本文档早期版本曾将 grounded_proxy 定义为 `0.6·correctness + 0.2·coverage + 0.1·order + 0.1·binding`。经过对 `examples/strategy_application/reward.py` 的代码审计，发现 `coverage`、`order`、`binding` 三个函数均依赖**英文关键词表面匹配**，在多语言、视觉、代码等题型上完全失效（如 `compute_entity_binding_consistency` 对非数值题直接 return 0.5）。考虑到训练数据覆盖 108 种题型，这三个指标会引入大量噪声，故**废弃**。

**最终版 Grounded Proxy = 多采样答题正确率（K=4）**：

$$\text{grounded\_proxy} = \frac{1}{K}\sum_{k=1}^{K} \mathbf{1}[\hat{a}_k = a^*], \quad K=4$$

**怎么算**：对同一条策略，让 Answer Model 独立答同一道题 **4 次**，统计答对的次数除以 4。结果只有 5 个档位：`{0.0, 0.25, 0.50, 0.75, 1.0}`。

```python
# 直观理解：
answers = [answer_model(strategy, problem) for _ in range(4)]
grounded_proxy = sum(is_correct(a, ground_truth) for a in answers) / 4
# 全对 → 1.0，答对3次 → 0.75，各半 → 0.50，答对1次 → 0.25，全错 → 0.0
```

**为什么 K=4 而不是 K=1**：

| 对比项 | K=1（原版） | K=4（新版） |
|--------|-----------|-----------|
| 信号取值 | 0 或 1（方差极大） | 0.0~1.0 五档（方差更小） |
| 抗随机性 | 差（一次运气不好就全错） | 好（反映策略真实"期望正确率"） |
| 适用题型 | 任意 | 任意（无语言/格式限制） |
| 计算成本 | 1次 Answer 调用 | 4次 Answer 调用（已有服务，并行） |

**grounded_proxy 的核心价值**：它衡量的是"**这个策略放到 Answer Model 手里，平均能答对几成**"——这和我们最终关心的指标（答题正确率）在语义上完全对齐，是真正 Grounded 的信号。

> **口径澄清（实现时必须保持一致）**：这里的 `grounded_proxy` 指的是 **K 次独立答题中“判为完全正确”的比例**，是一个硬统计量。  
> 它**不是**“soft correctness 平均分”。如果后续引入基于 `preferred_score/metrics` 的软判分路由，建议额外记录为 `soft_correctness_mean` 或 `router_correctness_mean`，不要和 `grounded_proxy` 混用，否则 reward 语义会漂移。

### 1.2.1 Correctness 判分器路由（基于 `preferred_score/metrics` 的分流，2026-03-02 增补）

> **结论**：该方案可行，但要先补齐数据链路。当前 `compute_answer_correctness` 的单一判分方式在跨 100+ 子任务下会引入系统性噪声；同时，当前 Stage1 数据样本并**没有**把 `preferred_score/metrics/subtask_name` 带进训练任务，所以 router 不能只写 reward 函数，必须先补 metadata ingress。  
> **核心改动**：将 `R_correctness` 从“单一判分器”升级为“任务类型路由判分器（router）”，并在数据构造阶段同步保留 `task_meta + ground_truths`。

#### A. 路由总原则

1. 先读任务 metadata：`preferred_score`、`metrics`、`subtask_name`
2. 先做统一 `normalize()`（见下文）
3. 根据任务类型选择判分器，不同类型输出到统一分值空间 `{0.0, 0.5, 0.8, 1.0}`
4. 无法识别类型时，使用 conservative fallback（精确匹配优先，禁用宽松 F1）

#### A.1 数据链路补齐（必须先做）

当前原始数据文件顶层已经包含：
- `preferred_score`
- `metrics`
- `subtask`
- `output_regex`

但当前 `train_strategy_generation.py` 在构造 Stage1 样本时只保留了：
- `problem_type`
- `examples`
- `problem`
- `ground_truth`

这会导致两类信息丢失：
- **task metadata 丢失**：router 无法知道该走 `multiple_choice_grade` 还是 `exact_str_match`
- **多参考答案丢失**：`target` 被压成单字符串后，长文本 / 多选 / 同义答案任务会被误判

因此推荐把 Stage1 样本结构扩成：

```python

    "examples": valid_fewshot,
    "num_shots": len(valid_fewshot),
    "problem": problem_text,
    "ground_truth": primary_target,      # 兼容旧逻辑
    "ground_truths": target_list,        # 新增：完整参考答案列表
    "task_meta": {                       # 新增：从原始 json 顶层继承
        "preferred_score": preferred_score,
        "metrics": metrics,
        "subtask_name": subtask_name,
        "output_regex": output_regex,
    },
    "source_problem_type": None,
}
```

> **推荐顺序**：先补 `task_meta + ground_truths` 进入 `StrategyGenerationTask`、validation outputs 和 rollout traces，再引入 router。本项目当前的主要缺口不是规则本身，而是 metadata 还没进链路。

> **C5 补全：few-shot examples 质量过滤**（在 `train_strategy_generation.py` 的 `_create_strategy_generation_dataset()` 中加入，避免低质量 few-shot 从上游污染策略生成器训练）：
>

#### B. 推荐判分规则（落地版）

| 任务类型 | 判分规则 | 备注 |
|---|---|---|
| `multiple_choice_grade` | 命中任一合法选项 target -> `1.0`，否则 `0.0` | 不使用 F1，避免软匹配噪声 |
| 数值型 `exact_str_match` | 规范化精确匹配 -> `1.0`；可解析数值且相对误差 `< 2%` -> `0.8`；否则 `0.0` | 适用 arithmetic / CRT / operators |
| 短标签/短字符串 `exact_str_match` | 命中任一参考答案（含规范化后）-> `1.0`；关键标签一致 -> `0.5`；否则 `0.0` | 适用异常类型、类别标签 |
| 长文本 `exact_str_match` 或带 `bleu/rouge` | 命中任一参考 -> `1.0`；token-F1 `>=0.8` -> `0.8`；`>=0.5` -> `0.5`；否则 `0.0` | 长文本任务不要只看 exact match |

> **为什么这样分档**：让 correctness 同时具备“可验证性（exact）”和“可用性（软容错）”，并避免把 F1 用在本不该软匹配的题型（如单选题）。

#### C. 统一规范化（必须先做）

在算 `R_correctness` 前统一执行：
- 去首尾空白
- 连续空白压缩为单空格
- 换行统一为空格
- 统一中英文引号
- 去除常见回答前缀模板（如 `Answer:`, `最终答案：`）
- 仅在任务声明不区分大小写时做 lower-case

> 这一步是高收益低风险改动：可显著减少“其实答对但格式不一致”的误判。

#### D. 针对当前 core 数据的直接落地建议

- `multiple_choice_grade`（54 subtasks）：保持硬判分（二值），不要引入 F1
- `exact_str_match`（20 subtasks）：拆为三档处理  
  1) 数值型 -> 数值容差  
  2) 短标签型 -> 多参考答案 + 规范化精确匹配  
  3) 长文本型 -> F1 分档  
- 带 `bleu/rouge` 的任务：优先走“长文本型”判分器，不要只看 exact match

#### E. 可直接实现的路由伪代码

```python
def compute_answer_correctness_router(pred, targets, task_meta):
    pred_n, targets_n = normalize(pred, task_meta), [normalize(t, task_meta) for t in targets]
    pscore = task_meta.get("preferred_score")
    metrics = set(task_meta.get("metrics", []))

    if pscore == "multiple_choice_grade":
        return 1.0 if match_any_option(pred_n, targets_n, task_meta) else 0.0

    if pscore == "exact_str_match" and is_numeric_task(task_meta):
        if exact_match(pred_n, targets_n):
            return 1.0
        if numeric_close(pred_n, targets_n, rel_tol=0.02, abs_tol=1e-9):
            return 0.8
        return 0.0

    if pscore == "exact_str_match" and is_short_label_task(task_meta):
        if exact_match(pred_n, targets_n):
            return 1.0
        if key_label_match(pred_n, targets_n):
            return 0.5
        return 0.0

    if pscore == "exact_str_match" or ("bleu" in metrics or "rouge" in metrics):
        if exact_match(pred_n, targets_n):
            return 1.0
        f1 = token_f1(pred_n, targets_n)
        if f1 >= 0.8: return 0.8
        if f1 >= 0.5: return 0.5
        return 0.0

    # fallback（保守）
    return 1.0 if exact_match(pred_n, targets_n) else 0.0
```

#### E.1 与 `grounded_proxy` 的关系（必须分开记）

- `correctness_router(pred, targets, task_meta)`：可返回 `{0.0, 0.5, 0.8, 1.0}`
- `grounded_proxy`：`K` 次独立答题中，`correctness_router(...) == 1.0` 的比例
- `soft_correctness_mean`：`K` 次独立答题的 router 分数均值

推荐日志字段：

```python
{
    "correctness": single_sample_router_score,   # 向后兼容旧字段
    "grounded_proxy": exact_success_count / K,   # 严格定义，不漂移
    "soft_correctness_mean": router_score_sum / K,
}
```

> 这样做的好处是：`grounded_proxy` 继续锚定“最终答对率”，`soft_correctness_mean` 则提供更平滑的辅助分析信号。

#### F. 建议的两点优化（在你方案基础上增强）

1. **容差建议用双阈值**：`relative + absolute`（`rel_tol=2%`, `abs_tol=1e-9`），避免接近 0 的数值被相对误差放大。  
2. **长文本 F1 的 tokenization 要按语言切换**：中文优先字粒度/结巴，英文用词粒度；否则 F1 波动会误导 reward。

#### G. 上线风险与回归指标（必须加）

- 风险 1：过宽容差导致“差不多对”被过奖  
  -> 监控 `near_miss_accept_rate`（0.8 分样本占比）  
- 风险 2：短标签 key-match 规则被投机  
  -> 对 0.5 分样本抽样人工审计  
- 风险 3：不同任务分布导致 reward scale 漂移  
  -> 分任务统计 `E[R_correctness | task_type]`

推荐上线后 3 个核心回归指标：
- `Spearman(final_reward, correctness_router)`（应持续高于旧版）
- `top_20pct_reward_bin_correctness`（高分 bin 正确率应显著高于总体）
- `OOD correctness`（不能因路由改动出现明显回落）

### 1.3 Outcome-Conditioned Scorer（升级版打分器）

原版 Scorer 是纯"看策略"打分，问题是它的打分标准和答题结果可能完全脱节。

**升级方案**：把生成的答案 + 答题结果（对/错）也作为输入喂给 Scorer，让它评估：
> "这个策略**是否导致了**成功/失败，以及它的**可复用性**"

```
[System]
You are a strategy effectiveness evaluator. You will be shown:
  1. The few-shot examples
  2. A problem-solving strategy extracted from those examples
  3. A new problem
  4. The answer that was generated using this strategy
  5. Whether the answer was correct

Your task: evaluate whether the strategy CAUSED the success/failure,
and how reusable this strategy is for similar problems.

Output JSON only. The full scoring rubric and JSON schema are defined in Section 1.3.1.

[User]
Few-shot examples: {examples_text}
Strategy: {strategy}
New problem: {problem}
Generated answer: {answer}
Answer correctness: {correct | incorrect}

Evaluate the strategy's effectiveness and generalizability.
```

这样 Scorer 变成了 **Outcome-Conditioned Scorer**，它的信号和 grounded_proxy 互补：
- **grounded_proxy**：客观测量"答对几成"（无语言限制，直接验证）
- **outcome_conditioned_scorer**：主观评估"策略的因果性和可迁移性"（提供更高层次的语义判断）

### 1.3.1 Outcome-Conditioned Scorer 的正式 Rubric（100 分制 + 封顶 + 惩罚项）

> **关键原则**：Scorer 评估的是"策略质量"，不是"文笔观感"。只要策略不能解释结果、不能执行、不能迁移，就不能给高分；即便答案碰巧答对，也不能放过。

#### 总分公式

先对 6 个维度分别打 `0~5` 分，再换算到 `100` 分：

$$
\text{raw\_score} = 20 \cdot (0.30A + 0.20B + 0.15C + 0.15D + 0.15E + 0.05F)
$$

$$
\text{final\_score\_100} = \min(\max(\text{raw\_score} - \text{penalty\_total}, 0), \text{cap\_ceiling})
$$

其中：
- `A = Outcome Support`：结果支持度，30%
- `B = Executability`：可执行性，20%
- `C = Example Grounding`：例题抽象质量，15%
- `D = Problem Coverage`：题目覆盖度，15%
- `E = Transfer Robustness`：迁移稳健性，15%
- `F = Clarity & Economy`：表达经济性，5%
- `oc_scorer = final_score_100 / 100.0`

#### 6 个维度的落地判分标准

| 维度 | 看什么 | 5 分锚点 | 3 分锚点 | 0 分锚点 | Scorer 必须给出的证据 |
|------|--------|---------|---------|---------|---------------------|
| `A. Outcome Support` | 策略是否真正解释成功或失败 | 能指出 1~2 个关键步骤如何直接导致答对/答错 | 部分相关，但结果里有明显"蒙对/蒙错"成分 | 策略与结果基本无关，或明显误导 | `outcome_evidence`：引用策略中的关键步骤，并说明它如何影响答案 |
| `B. Executability` | 是否可照着执行 | 有步骤、判断条件、检查点、必要时有 fallback | 有步骤但过于抽象，执行时仍要补脑 | 空话、目标陈述、口号式建议 | `procedure_evidence`：列出步骤数、是否有条件判断、是否有检查条件 |
| `C. Example Grounding` | 是否从 few-shot 提炼共性 | 抽到跨例题稳定规律，不依赖例题细节 | 有抽象，但仍夹带特定词、数值或个案痕迹 | 直接复述例题或拼贴答案 | `grounding_evidence`：指出抽象规则，或指出泄露的例题常数/实体 |
| `D. Problem Coverage` | 是否覆盖新题关键变量和约束 | 当前题的关键约束、变量、顺序基本都覆盖 | 覆盖一部分，但漏掉决定成败的关键条件 | 没碰到题眼 | `coverage_evidence`：列出已覆盖与缺失的关键约束 |
| `E. Transfer Robustness` | 换题/换表述时是否还能用 | 依赖问题结构，不依赖具体措辞、实体、数字 | 对同表述相似题可能有用，但稍变就脆弱 | 只对当前样例成立 | `transfer_evidence`：说明策略依赖结构还是依赖表面词 |
| `F. Clarity & Economy` | 是否简洁清楚 | 短而清楚，无冗余 | 略啰嗦但不影响执行 | filler 过多，影响理解 | `clarity_evidence`：指出冗余或确认无冗余 |

#### 硬性封顶规则（优先级高于连续打分）

只要触发，下述 ceiling 必须生效；多个同时触发时，取**最严格**的上限：

| 触发条件 | 总分上限 |
|----------|---------|
| 答案答对，但策略与答案过程明显无关 | `<= 55` |
| 答案答错，但策略大体正确，只是执行/计算失误 | `<= 75` |
| 策略包含核心错误步骤或误导性判断 | `<= 35` |
| 策略主要是空话模板，如"先理解题意、再逐步分析" | `<= 50` |
| 策略直接泄露答案、抄例题常数/实体、只会当前样例 | `<= 60` |

#### 惩罚项（和主维度分开扣）

| 触发条件 | 扣分 |
|----------|------|
| 空泛套话、正确但无操作价值 | `-15` |
| 例题记忆、答案泄露、表面复述 | `-15` |
| 关键步骤自相矛盾或逻辑反转 | `-20` |
| 缺少检查条件，容易把局部规则误用到全局 | `-10` |

#### 具体执行顺序（必须按这个顺序实现）

1. **先判结果关联**：先看 `answer correctness` 与 `generated answer`，再看策略是否真的支持这个结果；不要先被文字风格带跑。
2. **逐维打分**：A~F 每项必须给 `0~5` 整数或 `0.5` 档位分数，并给一句证据。
3. **触发封顶**：检查 5 类 ceiling flags，记录所有触发原因，取最小 `cap_ceiling`。
4. **叠加惩罚**：惩罚项可多项叠加，得到 `penalty_total`。
5. **后处理裁剪**：按 `final_score_100 = min(max(raw_score - penalty_total, 0), cap_ceiling)` 算最终分。
6. **归一化出 reward**：训练时传回 `final_score_01 = round(final_score_100 / 100.0, 4)`。

#### 推荐 JSON 输出协议

Scorer 不要只返回一个裸 `score`，必须返回可审计的结构化字段。这里区分两层：
- **模型返回字段**：只包含维度分、证据、cap flags、penalty flags、verdict
- **Python 回填字段**：`cap_ceiling`、`penalty_total`、`raw_score_100`、`final_score_100`、`final_score_01`

```json
{
  "dimension_scores": {
    "A_outcome_support": 4.5,
    "B_executability": 4.0,
    "C_example_grounding": 3.5,
    "D_problem_coverage": 4.0,
    "E_transfer_robustness": 3.5,
    "F_clarity_economy": 4.0
  },
  "dimension_evidence": {
    "outcome_evidence": "Step 2 aligns with the generated answer because it sets the comparison direction correctly.",
    "procedure_evidence": "The strategy contains ordered steps and one explicit check condition.",
    "grounding_evidence": "It abstracts the comparison rule without copying example-specific numbers.",
    "coverage_evidence": "Covers variables A/B and decision direction, but misses edge-case validation.",
    "transfer_evidence": "Depends on ratio structure rather than the exact entities in the examples.",
    "clarity_evidence": "Concise, one redundant sentence only."
  },
  "cap_flags": [
    "none"
  ],
  "penalties": [],
  "verdict": "mostly_effective_but_incomplete"
}
```

#### 工程落地要求（避免再次 reward hacking）

- **Prompt 只负责出 A~F、flags、penalties 和证据**，最终 `raw_score_100`、`final_score_100`、`final_score_01` 必须在 Python 侧二次计算，避免模型自己乱算权重。
- `reward_details` 中必须落盘这些字段：`oc_dimension_scores`、`oc_cap_flags`、`oc_penalties`、`oc_raw_score_100`、`oc_final_score_100`。
- 离线审计脚本要新增两个分布检查：
  - `cap_trigger_rate_by_type`：哪些题型经常触发 ceiling
  - `penalty_trigger_rate_by_type`：哪些题型经常因空话/泄露/矛盾被扣分
- 如果 `correctness=1` 但 `A_outcome_support <= 2.0` 的样本比例持续偏高，说明 Scorer 仍在给"碰巧答对"的策略放水，需要继续收紧 prompt。

#### 分数段解释（用于报表，不直接进 prompt）

| 区间 | 含义 |
|------|------|
| `90-100` | 高质量可复用策略，能解释结果，也能迁移 |
| `75-89` | 总体有效，存在少量缺口 |
| `60-74` | 部分有用，但不够稳，不宜高权重奖励 |
| `40-59` | 表面像策略，实则脆弱或泛泛 |
| `0-39` | 误导、无关、过拟合或明显 hacked |

#### 和 DreamGym 的关系（借鉴点与边界）

DreamGym 值得借的是"**可学性标准**"，不是直接把它的任务筛选 prompt 搬过来：
- 借鉴 `reward entropy` 的精神：优先把训练资源给"成功失败各半"、信息增益高的样本，而不是无脑堆简单样本。
- 借鉴 `challenging but feasible / meaningful variation / realistic / high quality / action consistency` 这些筛选标准，强调"可行但有挑战"。
- **不能直接照搬**：DreamGym 更偏任务和经验筛选；本项目这里要解决的是"策略 scorer 怎么避免只奖写得漂亮"。所以我们把这些标准压缩进 A~E 五个主维度里，变成能直接约束 reward 的 rubric。

### 1.4 最终奖励公式

$$R = 0.1 \cdot \text{format} + 0.4 \cdot \text{outcome\_conditioned\_scorer} + 0.5 \cdot \text{grounded\_proxy}$$

| 分项 | 权重 | 含义 | 为什么这样设置 |
|------|------|------|--------------|
| `format` | 0.1 | 策略是否有正确的结构（TYPE/STEPS/CHECK） | 保底，确保输出可解析 |
| `outcome_conditioned_scorer` | 0.4 | Scorer 评估策略因果性和可迁移性（见答案+结果） | 提供语义级的质量评估 |
| `grounded_proxy` | 0.5 | K=4 多采样答题正确率 | 最重要的客观信号，权重最高 |

**关键优点**：grounded_proxy（占 50%）完全基于客观可验证的答题结果，无语言限制，对 108 种题型全部适用。Scorer（40%）作为语义补充，被答题结果"校准"了（outcome-conditioned），不再是裸打分。

### Phase 0：离线审计（不改训练，约 1 周）

**目标**：在动任何训练参数之前，搞清楚 Scorer 是否真的和 correctness 相关，为后续奖励权重调整提供数据支撑。

---

#### 扩展现有文件：`analysis/scorer_correctness_auditor.py`

> **这个文件是什么**：一个离线数据分析脚本，读取现有的 rollout validation 记录，计算 Scorer 分数与真实答题正确率之间的 Spearman 相关系数，以及 grounded proxy 的分布情况，输出一份 JSON 格式的审计报告。当前仓库里已经有该文件，Phase 0 的工作应以**扩展/复用**为主，而不是重复新建。
>
> **目的**：在改任何训练配置之前，先有数据依据。如果 Scorer 分数和 correctness 完全不相关（Spearman < 0.35），就说明 Scorer 已经出现了 reward hacking，需要优先修 Scorer 而不是调权重。
>
> **预期效果**：运行一次，5 分钟内得到 `audit_report.json`，里面的 `spearman_scorer_correctness` 数值就是决定后续走哪条路的关键决策依据。

```python
"""
离线审计：读取已有 rollout traces / validation outputs，
计算 scorer 与 correctness 的 Spearman 相关性及 grounded proxy 分布。

输入：  validation_outputs 目录（validation_step*_worker*.json）
输出：  analysis/audit_report.json
"""
import json, glob, os, random
import numpy as np
from scipy.stats import spearmanr
import sys
sys.path.insert(0, ".")

# 注：coverage/order/binding 函数已从本脚本移除。
# grounded_proxy 新定义 = K=4 多采样正确率，见 hybrid_grounded_reward.py。
# 本脚本仅统计单次 correctness 作为 Phase 0 近似审计依据。

def load_rollout_records(val_dir: str) -> list[dict]:
    records = []
    for f in sorted(glob.glob(os.path.join(val_dir, "validation_step*_worker*.json"))):
        with open(f) as fp:
            data = json.load(fp)
        if isinstance(data, list):
            records.extend(data)
    return records

def run_audit(val_dir: str, output_dir: str = "analysis/") -> dict:
    records = load_rollout_records(val_dir)
    scorer_scores, correctnesses = [], []
    parse_ok = 0

    for r in records:
        sc = r.get("reward", {}).get("scorer", 0.0)
        co = r.get("reward", {}).get("correctness", 0.0)
        strategy = r.get("output", {}).get("strategy_extracted", "")

        scorer_scores.append(sc)
        correctnesses.append(co)
        if strategy:
            parse_ok += 1

    n = len(records)
    rho_sc, _ = spearmanr(scorer_scores, correctnesses)

    report = {
        "n_records": n,
        "parse_rate": parse_ok / n if n else 0,
        "spearman_scorer_correctness": round(rho_sc, 4),   # 关键决策依据
        "mean_scorer": round(float(np.mean(scorer_scores)), 4),
        "mean_correctness": round(float(np.mean(correctnesses)), 4),
        "top_scorer_bin_correctness": round(float(np.mean(
            [co for sc, co in zip(scorer_scores, correctnesses) if sc > 0.8]
        )), 4) if any(sc > 0.8 for sc in scorer_scores) else 0.0,
    }

    os.makedirs(output_dir, exist_ok=True)
    with open(os.path.join(output_dir, "audit_report.json"), "w") as f:
        json.dump(report, f, indent=2)

    print(f"[Audit] n={n}, parse_rate={report['parse_rate']:.2%}")
    print(f"[Audit] Spearman(scorer, correctness) = {rho_sc:.3f}  ← 关键！")
    print(f"[Audit] Top scorer(>0.8) actual correct = {report['top_scorer_bin_correctness']:.3f}")
    return report


def counterfactual_audit(
    val_records: list,
    answer_model_fn,    # I5 修复：(strategy: str, problem: str) -> str（返回字符串，不是 bool）
    correctness_fn,     # I5 新增：(pred: str, ground_truth: str) -> bool，负责判正确性
    n_sample: int = 200,
):
    """
    反事实采样审计：比较带策略 vs 不带策略的答题正确率差异。
    随机抽 n_sample 条记录（建议 200），对每条分别调用：
      - answer_model_fn(strategy, problem)  → 带策略答题，返回答案字符串
      - answer_model_fn("", problem)        → 不带策略直接答

    I5 修复：answer_model_fn 返回 str 而非 bool；
             由 correctness_fn 负责判断答案是否正确，
             避免调用方把 Answer Model 和正确性判断混为一体。

    correctness_fn 推荐使用：
      lambda pred, gt: compute_answer_correctness_router(pred, [gt], task_meta) == 1.0

    决策规则（写入 audit_report.json 后人工判断）：
      harm_rate > 15% → grounded_proxy 中加入惩罚项（见 hybrid_grounded_reward.py）
      harm_rate < 5%  → K=4 multi-sample correctness 已足够，无需额外惩罚
    """
    sample = random.sample(val_records, min(n_sample, len(val_records)))
    harm_count = help_count = neutral_count = 0

    for r in sample:
        problem  = r["input"]["problem"]
        strategy = r["output"]["strategy_extracted"]
        gt       = r["input"]["ground_truth"]

        ans_with    = answer_model_fn(strategy, problem)
        ans_without = answer_model_fn("", problem)          # 不给策略

        correct_with    = correctness_fn(ans_with,    gt)
        correct_without = correctness_fn(ans_without, gt)

        if correct_without and not correct_with:
            harm_count += 1
        elif not correct_without and correct_with:
            help_count += 1
        else:
            neutral_count += 1

    n = len(sample)
    result = {
        "harm_rate":    round(harm_count / n, 4),
        "help_rate":    round(help_count / n, 4),
        "neutral_rate": round(neutral_count / n, 4),
    }
    print(f"[Counterfactual] n={n}")
    print(f"  Strategy HELPS:   {result['help_rate']:.1%}")
    print(f"  Strategy HARMS:   {result['harm_rate']:.1%}  ← 关键指标")
    print(f"  Strategy NEUTRAL: {result['neutral_rate']:.1%}")
    return result
```

#### 新建文件：`examples/strategy_extraction/reward/strategy_ir_parser.py`

> **这个文件是什么**：一个纯程序的解析器（Parser），把策略文本按 TYPE / STEPS / CHECK / FALLBACK 四个 section 解析成结构化数据，同时提供新的 format reward 函数（区分"完全符合结构"和"只有标签没有结构"两种情况）。
>
> **目的**：把策略从"一段文字"变成"一个结构化对象"，让后续程序可以访问到 `strategy.steps[0]`、`strategy.checks` 等具体字段，进而计算步骤覆盖度、步骤顺序一致性等指标。
>
> **预期效果**：一旦有了这个解析器，grounded proxy 中的 coverage/order/binding 计算就可以针对"步骤粒度"进行，比直接分析原始文本更精准。Format reward 也从二值（有/无标签）升级为三值（结构完整 1.0 / 有标签无结构 0.3 / 无标签 0.0）。

```python
"""
策略结构化中间表示（IR）解析器。

对应 Prompt：strategy_structured_schema.toml
作用：把 <strategy>...</strategy> 文本解析为 StrategyIR dict，
      供 grounded proxy 计算和步骤级分析使用。

修复说明（对比旧版本）：
  Fix-1: StrategyIR 改为普通 dataclass，避免 TypedDict 在不同 Python
         版本下不支持直接实例化的问题（TypedDict 是类型注解工具，
         不是运行时构造器，直接 StrategyIR(...) 在 3.11 以下不总有效）。
  Fix-2: FALLBACK 使用独立正则（匹配 "- " 开头），与 CHECK 解析分离，
         避免两个 section 共用同一个 _CHECK_RE 时因边界判断顺序出错
         而导致 FALLBACK 内容混入 CHECK 列表。
  Fix-3: extract_strategy 改为相对导入，与 agent 中实际调用路径一致。
"""
import re
from dataclasses import dataclass, field
from typing import Optional

# ── 数据结构（dataclass 而非 TypedDict，保证所有 Python ≥ 3.8 可构造）──
@dataclass
class StrategyIR:
    """策略的结构化表示。"""
    type:     str        # 题型标签，e.g. "rate_comparison"
    steps:    list       # 解题步骤列表
    checks:   list       # 验证标准列表
    fallback: list       # 应急方案（可为空）
    fmt:      str = "structured"  # "structured" | "freetext_fallback"

# ── 正则（各 section 独立匹配，避免交叉干扰）──────────────────────────
# C1 补全：同时支持中英文 section 标记，适配多语言训练数据
_TYPE_RE     = re.compile(r"(?:TYPE|类型)\s*[:\：]\s*(.+)",                 re.IGNORECASE)
_STEPS_SEC   = re.compile(
    r"(?:STEPS|步骤)\s*[:\：](.*?)(?=(?:CHECK|验证|FALLBACK|备选)[:\：]|</strategy>|$)",
    re.DOTALL | re.IGNORECASE)
_CHECK_SEC   = re.compile(
    r"(?:CHECK|验证)\s*[:\：](.*?)(?=(?:FALLBACK|备选)[:\：]|</strategy>|$)",
    re.DOTALL | re.IGNORECASE)
_FALLBACK_SEC= re.compile(r"(?:FALLBACK|备选)\s*[:\：](.*?)(?=</strategy>|$)",
                          re.DOTALL | re.IGNORECASE)
_NUMBERED    = re.compile(r"^\s*\d+[\.\)]\s+(.+)", re.MULTILINE)   # "1. xxx" 或 "1) xxx"
_BULLET      = re.compile(r"^\s*[-*]\s+(.+)",      re.MULTILINE)   # "- xxx" 或 "* xxx"

def parse_strategy_ir(text: str) -> Optional[StrategyIR]:
    """
    解析结构化策略文本。
    成功返回 StrategyIR，失败返回 None。
    失败条件：缺少 TYPE、STEPS 少于 3 条、CHECK 少于 1 条。
    """
    type_m    = _TYPE_RE.search(text)
    steps_m   = _STEPS_SEC.search(text)
    check_m   = _CHECK_SEC.search(text)
    fallback_m= _FALLBACK_SEC.search(text)

    if not type_m or not steps_m:
        return None

    steps    = _NUMBERED.findall(steps_m.group(1))
    checks   = _BULLET.findall(check_m.group(1))   if check_m    else []
    fallback = _BULLET.findall(fallback_m.group(1)) if fallback_m else []

    if len(steps) < 3 or len(checks) < 1:
        return None

    return StrategyIR(
        type=type_m.group(1).strip(),
        steps=[s.strip() for s in steps],
        checks=[c.strip() for c in checks],
        fallback=[f.strip() for f in fallback],
    )

def compute_format_reward_structured(strategy_output: str) -> float:
    """
    三档 format reward：
      完整结构化（TYPE + STEPS≥3 + CHECK≥1）→ 1.0
      有 <strategy> 标签但解析失败            → 0.3
      无 <strategy> 标签                      → 0.0

    I4 修复：避免使用相对导入（在不同调用路径下会 ImportError），
    改为内联 extract_strategy 逻辑，消除跨包导入歧义。
    """
    # 内联 extract_strategy：直接解析 <strategy>...</strategy> 块
    import re as _re
    m = _re.search(r"<strategy>(.*?)</strategy>", strategy_output, _re.DOTALL)
    raw = m.group(1).strip() if m else None
    if not raw:
        return 0.0
    return 1.0 if parse_strategy_ir(raw) is not None else 0.3
```

---

#### 1.5.1 这一步为什么必须做

Spearman 只是第一层报警器，不是最终结论。必须先做 Phase 1.5，原因有四：

**原因 1：GRPO 真正吃的是组内排序，不是全局相关性**

```
同一题的一组 rollout：
  advantage_i = (reward_i - mean(reward_group)) / std(reward_group)

如果组内 std = 0：
  → 所有 advantage = 0
  → 即使全局 Spearman 看起来还行，训练也学不到东西
```

**原因 2：当前 correctness 很离散，Spearman 容易“看起来有信号，实际上很钝”**

Phase 0 还是单次 correctness 近似 grounded proxy，分布高度离散：
- `0.00`: 16,893 条
- `0.50`: 298 条
- `1.00`: 6,809 条

这种情况下，单个相关系数很适合“发现灾难”，不适合单独证明 reward 已经健康。

**原因 3：OC-Scorer 是新 prompt + 新 rubric + 新后处理的组合**

就算总分变好了，也要确认：
- A 维度是否真的区分“答对但策略无关”与“答错但策略总体正确”
- cap / penalty 是否在正确场景下触发
- 分数是不是仍然塌成几个固定档位

**原因 4：旧 reward 已确认负相关，不能把“和旧 reward 接近”当成验证目标**

真正该验证的是：
- `new_reward` 和 `correctness / grounded_proxy` 的关系
- 同题组内排序是否正确
- top-bin 是否真的更准
- 带策略是否帮助而不是伤害 Answer Model

---

#### 1.5.2 三层验证体系（两层硬门槛 + 一层条件确认）

```
层级    性质       耗时        作用
────────────────────────────────────────────────────────────────────
L1      硬门槛     45~60 min   验证 OC-Scorer 本身有没有基本判别力
L2      硬门槛     60~90 min   验证 reward 是否适合 GRPO 排序与梯度
L2.5    硬门槛     90~150 min  验证“用策略是否显著优于不用策略”（paired uplift）
L3      条件触发   1~2 h       在 L1/L2/L2.5 通过后，做一次小规模学习确认
────────────────────────────────────────────────────────────────────
```

**执行原则**：
- `L1` 不过：只改 rubric / prompt / postprocess，不碰训练
- `L2` 不过：先改 reward 配方、K 值、group 设计，不跑完整训练
- `L2.5` 不过：优先修策略提取质量与 correctness 路由，再看采样/seed 设计
- `L1 + L2 + L2.5` 通过后：才允许开启 `L3` 或直接进入完整训练
- `L3` 是确认项，不是阻塞代码实现的前提

#### 1.5.3 L1：OC-Scorer 输出质量验证（45~60 分钟）

**目标**：验证新的 rubric 能否在离线数据上产出“连续、可解释、与结果方向一致”的分数，而不是继续奖励写得漂亮的废话策略。

**这一步必须做双切片，而不是只看一个样本池**：

1. `Boundary Slice`：能力边界题型
   - 自动从 `difficulty_stats` 或 `audit_report` 中选 `mean_correctness` 落在 `[0.20, 0.45]` 的题型
   - 目标样本数：`300~500`
   - 用途：做高敏感度 stress test，观察 reward 是否真能区分好坏

2. `Stratified Natural Slice`：全量分层自然分布切片
   - 按题型分层采样，总量 `500~1000`
   - 保持原始正确率分布，不强制 50/50
   - 用途：检查 reward 在真实分布下是否稳定

> **重要修正**：`Boundary Slice` 可以做 balanced sampling 作为 stress test，但**不能只报告这个结果**。必须同时报告自然分布切片结果。

**强制数据要求**：
- 必须有 `strategy`、`problem`、`examples_text`
- 必须有 `generated answer` 文本；如果 rollout 没保存 answer：
  - 优先重新调用 Answer Model 补生成
  - 补不回来就丢弃该样本
- **禁止**使用“只给 correctness label，不给 answer text”的 fallback，因为这会弱化 Outcome-Conditioned 评估

**建议脚本职责**：`analysis/validate_oc_scorer.py`

```python
"""
L1 验证的关键职责：
1. 从 val records 构造两个切片：
   - boundary_slice: 300~500 条，自动选边界题型
   - natural_slice: 500~1000 条，按题型分层保留原始分布
2. 如果 answer 文本缺失：
   - 调用 Answer Model 补生成；失败则丢弃
3. 调用新 OC-Scorer JSON rubric
4. Python 侧确定性计算 final_score_01
5. 输出以下指标：
   - Spearman(new_oc_scorer, correctness)
   - top_20pct_correctness_uplift
   - new_score_std
   - dimension A/B/C/E 的正确/错误分布差异
   - cap / penalty 触发频率
   - bootstrap 95% CI
"""
```

**L1 核心指标**：

| 指标 | 为什么要看 | 通过线 |
|------|-----------|-------|
| `Spearman(new_oc_scorer, correctness)` | 检查全局单调性是否至少正转 | `> 0.15`（boundary）且 `> 0.10`（natural） |
| `top_20pct_correctness_uplift` | 看高分样本是否真的更准 | 高分 bin 正确率比全体均值高 `>= 8%` |
| `new_score_std` | 防止分数继续塌成少数几个档位 | `> 0.12` |
| `A_outcome_support` gap | 检查结果支持度是否真的区分对错 | `mean(A|correct) - mean(A|incorrect) >= 0.8` |
| `cap/penalty trigger sanity` | 检查 rubric 是否真的抓到空话和无关策略 | 不能接近 0，也不能异常爆炸 |
| `bootstrap 95% CI` | 防止小样本偶然波动 | 下界不能穿过 0 太多 |

**L1 不通过时优先修改顺序**：

1. 先改 prompt 中的证据要求和 flag 定义
2. 再改 Python 后处理中的 ceiling / penalty 映射
3. 最后才改总权重

**L1 后推荐顺手加一个离线 weight sweep**：
- 在固定离线记录上比较：
  - `0.05 format + 0.20 oc + 0.75 gp`
  - `0.05 format + 0.30 oc + 0.65 gp`
  - `0.10 format + 0.40 oc + 0.50 gp`
- 用相同切片比较 `Spearman`、`top-bin uplift`、`help/harm`
- 默认先选最保守、最稳定的，而不是最“漂亮”的组合

#### 1.5.4 L2：组内排序能力 + 有效梯度可用性（60~90 分钟）

**目标**：验证新 reward 是否适合 GRPO，而不是只在全局上看起来有相关性。

**首先检查验证集是否存在同题多 rollout**：

```python
def check_group_structure(val_dir: str):
    """
    以 (problem, examples_text) 作为 group key，
    统计每个 group 有多少条 rollout。
    """
```

然后分两种情况：

1. **优先方案：真实组内 Pairwise**
   - 如果 val 集里已有同题多 rollout，直接在这些真实组里比较
   - 核心问题：同组内“更高 correctness / grounded_proxy”的策略，是否被新 reward 排更前

2. **如果 val 集没有足够组内样本，不要把跨样本 Pairwise 当主结论**
   - 跨样本 Pairwise 只能做补充
   - 更合理的补救是：离线补采 `50~100` 个 prompt group，每组生成 `4` 条策略
   - 然后对这些真实组做排序验证

> **重要修正**：跨样本 Pairwise 只能放进报告的 supplement，不能作为完整训练前的唯一放行依据。

**建议脚本职责**：`analysis/validate_pairwise.py`

```python
"""
L2 输出至少要包含：
1. pairwise_accuracy_in_group
2. pairwise_margin_calibration
3. effective_gradient_group_rate
4. reward_std_within_group
5. top_bin_help_rate / harm_rate
6. 对旧 reward 与新 reward 的并排比较
"""
```

**L2 核心指标**：

| 指标 | 含义 | 通过线 |
|------|------|-------|
| `pairwise_accuracy_in_group` | 同题组内排序是否正确 | `> 0.60` |
| `effective_gradient_group_rate` | 组内 reward std 足够大、不至于梯度消失 | `> 0.55` |
| `reward_std_within_group` | 组内差异是否可学习 | 显著高于旧 reward |
| `top_20pct_help_rate` | 高分策略是否更多帮助而不是伤害 | `help > harm` 且净增益为正 |
| `cross-sample pairwise` | 仅补充说明全局方向 | 不作为硬门槛 |

**如果 L2 不通过，优先调整**：

1. 下调 `oc_scorer` 权重，优先试 `0.20~0.30`
2. 上调 `grounded_proxy` 到 `0.65~0.75`
3. 再考虑调 `K` 或 group_size
4. 最后才考虑更复杂的探索策略

#### 1.5.5 L2.5：策略有效性统计检验（paired uplift audit，需额外多 seed 推理，90~150 分钟）

> **定位**：这是 Phase 1.5 新增的“因果有效性”硬门槛。  
> **为什么加**：L1/L2 主要验证“reward 形状是否健康、组内排序是否可学”，但还不能直接回答“策略到底有没有帮助解题”。  
> **本节回答的问题**：在同题同 seed 的配对对比中，`with_strategy` 是否显著优于 `without_strategy`。

**这一步需要额外运行（不是纯离线日志）**：
- 固定评测集（建议 200~500 题，按题型分层）
- 多随机种子（建议 5~10 个）
- 双臂对照：
  1) `with_strategy`：按当前 pipeline 提取并应用策略  
  2) `without_strategy`：禁用策略，仅保留 Answer Model 常规解题链路

**统计单位（必须配对）**：

对每个 seed 计算一次总体准确率增益：

$$
\Delta_s = Acc^{with}_s - Acc^{without}_s
$$

然后对 $\{\Delta_s\}_{s=1}^{S}$ 做统计检验（双侧配对 t 检验）。

> 注意：不要把“每道题每次采样”当独立样本做 t-test，会产生伪重复（pseudo-replication）。

**建议脚本职责**：`analysis/strategy_uplift_auditor.py`

```python
"""
L2.5 关键职责：
1) 读取固定数据集与 seeds，分别跑 with_strategy / without_strategy
2) 按 seed 聚合准确率，得到 paired deltas: delta_s
3) 输出：
   - strategy_uplift_mean
   - strategy_uplift_ci95  (bootstrap or t-based CI)
   - strategy_uplift_pvalue (two-sided paired t-test)
   - strategy_uplift_effect_size_dz (Cohen's dz)
4) 可选：
   - 分 problem_type 子报告 + FDR(BH) 校正后的 p 值
"""
```

**L2.5 通过线（建议三条件同时满足）**：

| 指标 | 含义 | 通过线 |
|------|------|-------|
| `strategy_uplift_mean` | 使用策略后的平均增益 | `> 0` |
| `strategy_uplift_pvalue` | 双侧配对 t 检验显著性 | `< 0.05` |
| `strategy_uplift_ci95_low` | 95% 置信区间下界 | `> 0`（强通过） |
| `strategy_uplift_effect_size_dz` | 配对效应量 | `>= 0.2`（建议） |

**不通过时优先排查**：
1. 先查策略提取质量（parse 成功但内容无效）  
2. 再查 correctness 路由规则是否过严/过松  
3. 最后再查采样温度、seed 数量是否不足

```
  ├── 若 grounded_proxy 有任何上升趋势（哪怕未达 3% 门槛）
  │     → 直接进入完整训练（L3 是确认项，不是阻塞项）
  │     → 在报告中标注"L3 未达标但趋势正向"

            1. 确认全零组比例（all_zero_group_rate > 60% 时降低难题权重）
            2. 确认 few-shot examples 质量（filter_valid_fewshot_examples 是否生效）

```

#### 紧急修复：Scorer Prompt 重写（解决三档离散化问题）

> **问题诊断**：当前 Scorer 分数分布极度离散（0.15 占 21.5%、0.70 占 40.5%、1.00 占 30.9%），说明 Scorer 的 prompt 导致了输出塌陷——它不是在评估策略质量，而是在做三档分类。这是 Scorer 信号失效的直接原因之一。
>
> **修复方法**：不用"单一主观分"，改成上面 `A~F 六维 + 封顶规则 + 惩罚项` 的 outcome-conditioned rubric。Prompt 负责产出结构化判定，Python 侧负责确定性算分。

```
[重写后的 Outcome-Conditioned Scorer Prompt]

[System]
You are a strict evaluator of STRATEGY QUALITY, not writing style.

You must assess whether the strategy actually explains the observed success/failure
and whether it can transfer to similar unseen problems.

Score six dimensions on a 0-5 scale:
- A_outcome_support
- B_executability
- C_example_grounding
- D_problem_coverage
- E_transfer_robustness
- F_clarity_economy

Hard cap rules:
- correct answer but strategy clearly unrelated -> cap <= 55
- wrong answer but strategy mostly right, only execution/calculation failed -> cap <= 75
- core wrong step or misleading decision rule -> cap <= 35
- mostly generic template language -> cap <= 50
- leaked answer / copied example constants or entities / overfit to current sample -> cap <= 60

Penalty rules:
- generic but not operational -> -15
- memorization / answer leakage / surface copying -> -15
- contradiction or logic reversal -> -20
- missing check condition, likely over-applies local rule globally -> -10

Evidence requirements:
- For every dimension, provide one short evidence sentence.
- Explicitly cite which step in the strategy supports or harms the generated answer.
- If you trigger a cap or penalty, include the reason string in the output.

Important:
- Do not reward a strategy just because the answer is correct.
- Do not punish a good strategy too harshly if the final error is only arithmetic execution.
- Use decimal scores when needed (e.g. 3.5, 4.5). Avoid collapsing to a few fixed values.
- Do NOT compute the weighted final score yourself unless asked; the caller will recompute it.

Output ONLY valid JSON with this schema:
{
  "dimension_scores": {
    "A_outcome_support": 0-5,
    "B_executability": 0-5,
    "C_example_grounding": 0-5,
    "D_problem_coverage": 0-5,
    "E_transfer_robustness": 0-5,
    "F_clarity_economy": 0-5

    "outcome_evidence": "...",
    "procedure_evidence": "...",
    "grounding_evidence": "...",
    "coverage_evidence": "...",
    "transfer_evidence": "...",
    "clarity_evidence": "..."
  },
  "cap_flags": ["..."],
  "penalties": ["..."],
  "verdict": "..."
}

[User]
Few-shot examples: {examples_text}
Strategy: {strategy}
Problem: {problem}
Generated answer: {answer}
Answer was: {correct | incorrect}

Evaluate the strategy with the rubric. JSON only.
```

> **Python 侧后处理**：收到 JSON 后，不信任模型自行计算的总分，只读取 `dimension_scores`、`cap_flags`、`penalties`，按 1.3.1 节的公式在 `hybrid_grounded_reward.py` 中确定性计算 `final_score_100` 和 `final_score_01`。
>
> **预期效果**：Scorer 分布从三档离散 → 连续分布；同时通过 ceiling 和 penalty 明确压制"答案碰巧正确"、"表面像策略"、"直接抄例题"三类 reward hacking。

```python
"""
混合接地奖励（Hybrid Grounded Reward，K=4 多采样版本）。

关键口径：
  grounded_proxy        = K 次答题中“严格判对”的比例，只能取 {0, .25, .50, .75, 1}
  soft_correctness_mean = K 次 router correctness 分数的均值（可取 0/.5/.8/1 的平均）
  oc_scorer             = 结果条件版策略评分器

三者必须分开记录，不可混用。
"""
import asyncio
import json
import re
from typing import Awaitable, Callable

from examples.strategy_application.reward import compute_answer_correctness_router

AsyncAnswerFn = Callable[[str], Awaitable[str]]

async def evaluate_strategy_k_samples(
    strategy: str,
    targets: list[str],
    task_meta: dict,
    answer_fn: AsyncAnswerFn,
    k: int = 4,
) -> dict:
    """
    answer_fn: 零参数 async callable，内部闭包已绑定
               base_url/api_key/model/problem/temperature/max_tokens 等上下文。
    """
    raw_answers = await asyncio.gather(*[answer_fn(strategy) for _ in range(k)])

    scores = []
    exact_success = 0
    for raw in raw_answers:
        extracted = extract_answer(raw) or ""
        score = compute_answer_correctness_router(
            pred=extracted,
            targets=targets,
            task_meta=task_meta,
        )
        scores.append(score)
        if score == 1.0:
            exact_success += 1

    return {
        "answer_raw_list": raw_answers,
        "grounded_proxy": exact_success / k,
        "soft_correctness_mean": sum(scores) / k if scores else 0.0,
        "single_sample_correctness": scores[0] if scores else 0.0,
        "router_scores": scores,
    }


def select_representative_answer(answer_raw_list: list[str], router_scores: list[float]) -> dict:
    """
    给 OC-Scorer 选一个不自相矛盾的代表答案。
    推荐规则：
      1) 若存在 score==1.0 的样本，优先选第一条严格正确答案
      2) 否则选 router_score 最高的一条
    """
    if not answer_raw_list:
        return {"representative_answer": "", "representative_label": "incorrect"}

    best_idx = max(range(len(answer_raw_list)), key=lambda i: router_scores[i])
    for i, score in enumerate(router_scores):
        if score == 1.0:
            best_idx = i
            break
    label = "correct" if router_scores[best_idx] == 1.0 else "incorrect"
    return {
        "representative_answer": answer_raw_list[best_idx],
        "representative_label": label,
    }

# OC_SCORER_SYSTEM_PROMPT 见 Section 1.3.1 rubric，此处占位（实际部署时替换为完整 prompt）
OC_SCORER_SYSTEM_PROMPT = (
    "You are a strict evaluator of STRATEGY QUALITY, not writing style.\n"
    "Score six dimensions on a 0-5 scale: A_outcome_support, B_executability, "
    "C_example_grounding, D_problem_coverage, E_transfer_robustness, F_clarity_economy.\n"
    "Apply hard cap and penalty rules as defined in the rubric.\n"
    "Use decimal scores (e.g. 3.5, 4.5). Avoid collapsing to a few fixed values.\n"
    "Do NOT compute the weighted final score yourself; output JSON only."
)

_CAP_FLAG_MAP = {
    "correct_but_unrelated":   55,
    "wrong_but_strategy_ok":   75,
    "core_wrong_step":         35,
    "generic_template":        50,
    "leaked_answer":           60,
}
_PENALTY_MAP = {
    "generic_not_operational": 15,
    "memorization_leakage":    15,
    "contradiction":           20,
    "missing_check":           10,
}

def _compute_cap_ceiling(cap_flags: list[str]) -> float:
    """取所有触发 cap 的最严格上限（最小值）。"""
    ceilings = [_CAP_FLAG_MAP[f] for f in cap_flags if f in _CAP_FLAG_MAP]
    return min(ceilings) if ceilings else 100.0

def _compute_penalty_total(penalties: list[str]) -> float:
    """惩罚项可多项叠加。"""
    return sum(_PENALTY_MAP.get(p, 0) for p in penalties)

def build_outcome_conditioned_scorer_prompt(
    examples_text: str,
    strategy: str,
    problem: str,
    answer: str,
    correctness_label: str,
) -> list[dict]:
    """
    构造 Outcome-Conditioned Scorer 的 messages 列表（OpenAI chat 格式）。
    correctness_label: "correct" | "incorrect"
    """
    return [
        {"role": "system", "content": OC_SCORER_SYSTEM_PROMPT},
        {"role": "user", "content": (
            f"Few-shot examples:\n{examples_text}\n\n"
            f"Strategy:\n{strategy}\n\n"
            f"Problem:\n{problem}\n\n"
            f"Generated answer:\n{answer}\n\n"
            f"Answer was: {correctness_label}\n\n"
            "Evaluate the strategy with the rubric. Output valid JSON only."
        )},
    ]

def parse_oc_scorer_response(raw_json: str) -> float:
    """
    解析 OC-Scorer 原始 JSON → final_score_01。
    Python 侧确定性计算，不信任模型自算的分数。
    解析失败时返回保守默认值 0.3（避免 Scorer 服务抖动清零训练信号）。
    """
    try:
        obj = json.loads(raw_json)
    except Exception:
        # 尝试提取 JSON 代码块
        import re as _re
        m = _re.search(r"```(?:json)?\s*(\{.*?\})\s*```", raw_json, _re.DOTALL)
        if m:
            try:
                obj = json.loads(m.group(1))
            except Exception:
                return 0.3
        else:
            return 0.3

    dims = obj.get("dimension_scores", {})
    raw_100 = 20 * (
        0.30 * float(dims.get("A_outcome_support",  0))
      + 0.20 * float(dims.get("B_executability",     0))
      + 0.15 * float(dims.get("C_example_grounding", 0))
      + 0.15 * float(dims.get("D_problem_coverage",  0))
      + 0.15 * float(dims.get("E_transfer_robustness",0))
      + 0.05 * float(dims.get("F_clarity_economy",   0))
    )
    cap      = _compute_cap_ceiling(obj.get("cap_flags", []))
    penalty  = _compute_penalty_total(obj.get("penalties", []))
    final_100 = min(max(raw_100 - penalty, 0.0), cap)
    return round(final_100 / 100.0, 4)

def compute_hybrid_reward(
    format_r:     float,
    oc_scorer_r:  float,
    grounded_proxy: float,
    format_weight:  float = 0.1,
    scorer_weight:  float = 0.4,
    proxy_weight:   float = 0.5,
) -> float:
    """
    最终奖励公式：R = 0.1·format + 0.4·oc_scorer + 0.5·grounded_proxy。
    权重之和必须为 1.0，调用方可通过参数覆盖默认权重。
    """
    assert abs(format_weight + scorer_weight + proxy_weight - 1.0) < 1e-6, \
        f"Reward weights must sum to 1.0, got {format_weight+scorer_weight+proxy_weight}"
    return round(
        format_weight  * format_r
      + scorer_weight  * oc_scorer_r
      + proxy_weight   * grounded_proxy,
        4
    )


# ─────────────────────────────────────────────────────────────────
#  R3 补全：全零组降级处理
#  当组内所有 rollout 的 grounded_proxy = 0 时（题目对当前模型太难），
#  降级使用 soft_correctness_mean 提供微弱梯度，避免 GRPO 梯度消失。
# ─────────────────────────────────────────────────────────────────

def select_effective_proxy(
    grounded_proxy:       float,
    soft_correctness_mean: float,
    group_gp_values:      list[float],
    soft_fallback_scale:  float = 0.3,
) -> float:
    """
    若组内全部 grounded_proxy = 0，降级到 soft_correctness_mean 提供微弱梯度。
    soft_fallback_scale 控制降级信号强度（默认 0.3，避免软信号过度主导）。

    调用位置：rollout_async() 中汇总同组奖励后、传给 GRPO advantage 计算前。
    """
    if group_gp_values and max(group_gp_values) == 0.0:
        return soft_correctness_mean * soft_fallback_scale
    return grounded_proxy
```

#### 新建文件：`analysis/preference_pair_miner.py`

> **这个文件是什么**：一个离线数据挖掘脚本，优先读取现有 `rollout_traces/rollout_traces.jsonl`，若只保留了 validation 结果则从 `validation_global_step*.json` 聚合记录，按"同一道题 + 同一批 few-shot 示例"分组，在同组内找出 grounded_proxy 差距 ≥ 0.25 的策略对，标记为 winner 和 loser，输出 `preference_pairs.jsonl`。
>
> **目的**：为后续的 RSFT（只用 winner 做 SFT）和未来的 DPO/KTO（用 winner/loser 对做偏好学习）提供数据来源。这是唯一不需要额外 LLM 调用、纯靠已有 rollout 数据就能获得的对比监督信号。
>
> **预期效果**：每轮训练后产出几百到几千对 preference pairs，质量随 grounded_proxy 改进而提升，逐轮积累成高质量的偏好数据库。

```python
"""
离线 Preference Pair 挖掘器。

规则：
  - 按 sample_key 分组（sha1(problem_type + problem + fewshot_hash)）
  - winner.grounded_proxy - loser.grounded_proxy >= 0.25
  - winner.correctness >= loser.correctness（防止只有 coverage 高但答错的策略当 winner）
  - 每个 sample_key 最多保留 top1 vs bottom1 一对
"""
import json, hashlib, os, glob

MARGIN_THRESHOLD = 0.25  # winner 和 loser 的 grounded_proxy 最小差距

def make_sample_key(problem_type: str, problem: str, examples: list) -> str:
    """为同一道题+同一批示例生成唯一 key，用于分组比较不同策略。"""
    raw = problem_type + "|" + problem + "|" + json.dumps(examples, sort_keys=True)
    return hashlib.sha1(raw.encode()).hexdigest()[:12]

def _get_grounded_proxy(record: dict) -> float:
    """
    I6 补全：兼容旧格式 traces（Phase 2 之前）。
    优先读 grounded_proxy；若字段不存在（旧格式），降级到 correctness 并发出警告。
    """
    reward = record.get("reward", {})
    if "grounded_proxy" in reward:
        return float(reward["grounded_proxy"])
    import warnings
    warnings.warn(
        "Record missing 'grounded_proxy', falling back to 'correctness'. "
        "Use Phase 2+ rollout traces for reliable preference mining.",
        stacklevel=3,
    )
    return float(reward.get("correctness", 0.0))

def mine_pairs(traces_path: str, output_path: str) -> list:
    # 按 sample_key 分组
    groups: dict = {}
    old_format_count = 0
    with open(traces_path) as f:
        for line in f:
            r = json.loads(line)
            if "grounded_proxy" not in r.get("reward", {}):
                old_format_count += 1
            key = r.get("sample_key", make_sample_key(
                r["problem_type"], r["input"]["problem"], r["input"]["examples"]
            ))
            groups.setdefault(key, []).append(r)

    total = sum(len(g) for g in groups.values())
    if total > 0 and old_format_count / total > 0.5:
        raise RuntimeError(
            f"{old_format_count}/{total} records lack 'grounded_proxy'. "
            "Please use Phase 2+ rollout traces for reliable preference mining."
        )
    if old_format_count > 0:
        import warnings
        warnings.warn(f"{old_format_count} records use old format fallback (correctness→grounded_proxy)")

    pairs = []
    for key, group in groups.items():
        if len(group) < 2:
            continue
        group.sort(key=lambda x: _get_grounded_proxy(x), reverse=True)
        winner, loser = group[0], group[-1]
        margin = _get_grounded_proxy(winner) - _get_grounded_proxy(loser)
        if margin < MARGIN_THRESHOLD:
            continue
        # I6 补全：兼容旧格式——correctness 字段名也可能不同
        w_correct = winner["reward"].get("correctness", _get_grounded_proxy(winner))
        l_correct = loser["reward"].get("correctness",  _get_grounded_proxy(loser))
        if w_correct < l_correct:
            continue  # 不选"覆盖率高但答错"的策略当 winner
        pairs.append({
            "sample_key": key,
            "problem_type": winner["problem_type"],
            "fewshot_examples_text": winner["input"].get("user_prompt", ""),
            "winner_strategy": winner["output"]["strategy_extracted"],
            "loser_strategy":  loser["output"]["strategy_extracted"],
            "winner_grounded_proxy": _get_grounded_proxy(winner),
            "loser_grounded_proxy":  _get_grounded_proxy(loser),
            "winner_correctness":    w_correct,
            "margin": margin,
        })

    os.makedirs(os.path.dirname(output_path), exist_ok=True)
    with open(output_path, "w") as f:
        for p in pairs: f.write(json.dumps(p, ensure_ascii=False) + "\n")
    print(f"[PreferenceMiner] {len(pairs)} pairs from {len(groups)} groups → {output_path}")
    return pairs
```

#### 新建文件：`analysis/winner_strategy_distiller.py`

> **这个文件是什么**：用 preference pairs 中的 winner 策略构建 SFT 训练数据集，按 90% winner + 10% anchor（原始高质量样本）的比例混合，输出 `winner_rsft_dataset.jsonl`，供后续 SFT 脚本使用。
>
> **目的**：RSFT（Rejection Sampling Fine-Tuning）是最保守的蒸馏方式——只用"被证明有效的策略"做监督学习，不需要 KTO/DPO 的复杂偏好训练框架，可以直接复用现有 SFT 代码。效果是让模型的"起点"更好，RL 训练从更高的基准线出发。
>
> **预期效果**：RSFT 后模型生成的策略在 grounded_proxy 上提升 ≥ 3%，OOD correctness 不下降（避免过拟合 winner 策略的领域分布）。

```python
"""
Winner 策略蒸馏数据集构建器。

从 preference_pairs.jsonl 提取 winner 策略，
混合少量 anchor data（高质量原始示例），构建 RSFT 数据集。

数据比例：90% winner strategies + 10% anchor data
"""
import json, random, os

def build_winner_rsft_dataset(
    preference_pairs_path: str,
    output_path: str,
    # I7 修复：anchor_data_path 改为可选，并明确两种来源策略
    anchor_data_path: str = None,
    anchor_ratio: float = 0.1,
    seed: int = 42,
) -> None:
    """
    构建 winner RSFT 数据集。

    I7 补全：anchor_data 来源两种策略，优先级如下：
      1. 若提供 anchor_data_path（如原始训练集 jsonl），直接加载作为锚数据
      2. 若未提供，从 preference_pairs 中取 margin 最小的样本做 soft-anchor
         （有训练信号但差异小，防止分布漂移，同时利用已有数据）

    推荐 anchor_data_path 使用：原始 Stage1 训练集（strategy_gen_train.jsonl）
    或 Phase 0 审计中 grounded_proxy=1.0 的高质量样本子集。
    """
    random.seed(seed)
    pairs = [json.loads(l) for l in open(preference_pairs_path)]

    winner_samples = [{
        "problem_type": p["problem_type"],
        "input":  p["fewshot_examples_text"],
        "output": p["winner_strategy"],
        "source": "winner",
        "grounded_proxy": p["winner_grounded_proxy"],
    } for p in pairs]

    n_anchor = max(1, int(len(winner_samples) * anchor_ratio / (1 - anchor_ratio)))

    if anchor_data_path and os.path.exists(anchor_data_path):
        # 策略 1：使用外部锚数据集（推荐：原始训练集或高质量样本）
        all_anchors = [json.loads(l) for l in open(anchor_data_path)]
        random.shuffle(all_anchors)
        anchor_samples = [{**a, "source": "anchor"} for a in all_anchors[:n_anchor]]
    else:
        # 策略 2：soft-anchor，从 pairs 中取 margin 最小的样本
        sorted_by_margin = sorted(pairs, key=lambda x: x["margin"])
        anchor_samples = [{
            "problem_type": p["problem_type"],
            "input":  p["fewshot_examples_text"],
            "output": p["winner_strategy"],
            "source": "soft_anchor",
            "grounded_proxy": p["winner_grounded_proxy"],
        } for p in sorted_by_margin[:n_anchor]]
        if not anchor_data_path:
            import warnings
            warnings.warn(
                "anchor_data_path not provided; using soft-anchor from low-margin pairs. "
                "For better diversity, pass the original training set as anchor_data_path."
            )

    dataset = winner_samples + anchor_samples
    random.shuffle(dataset)

    os.makedirs(os.path.dirname(output_path), exist_ok=True)
    with open(output_path, "w") as f:
        for d in dataset: f.write(json.dumps(d, ensure_ascii=False) + "\n")
    print(f"[Distiller] {len(winner_samples)} winners + {len(anchor_samples)} anchors"
          f" = {len(dataset)} total → {output_path}")
```

#### Phase 3 验收

- val grounded_proxy 提升 ≥ 3%（RSFT 后）
- OOD correctness 不下降超过 2%
- 若连续两轮无提升，再考虑 DPO/KTO

> **R5 补全：RSFT 灾难性遗忘风险（RL 之后做 SFT 的特殊注意）**
>
> Phase 3 RSFT 发生在 Phase 2 RL 之后，顺序与"SFT 先、RL 后"的标准经验相反，存在覆盖 RL 学到的分布的风险。推荐以下防护措施：
>
> 1. **优先使用 LoRA 而非全参微调**：只训 LoRA adapter（建议 rank=8, alpha=16），不动 base weights，最大程度保护 RL 学到的分布。
> 2. **限制训练步数**：RSFT 最多 500 steps；每 100 steps 验证一次 grounded_proxy，若连续 2 次不涨则提前停止。
> 3. **merge 前验证**：LoRA merge 到 base 之前，在 200 条 val 样本上跑一次，确认 grounded_proxy 未下跌超过 1%。
> 4. **若不支持 LoRA**（框架限制）：在 RSFT 训练数据中额外混入 15% 的 Phase 2 RL rollout 记录（`anchor_ratio` 机制已支持），保持 RL 分布的"记忆"。

#### 新建文件：`analysis/difficulty_stats_updater.py`

> **这个文件是什么**：每轮训练结束后，读取 validation outputs，统计各 `problem_type` 的答题成功率（以 grounded_proxy > 0.5 为"成功"），用指数移动平均（EMA）更新 `difficulty_stats.json` 中每种题型的历史成功率和采样权重。
>
> **目的**：为下一轮训练提供动态采样权重。成功率 ~50% 的题型（模型"刚好在边界上"）采样权重最高；成功率显著偏离 50% 的题型权重降低；对已确认不适配当前链路的题型（如 `excluded=true`）直接跳过。
>
> **预期效果**：能力边界题型（0.3 ≤ p ≤ 0.7）的采样占比从随机的 ~40% 提升到 > 50%；排除无效题型（如 mnist_ascii）后训练效率提升 15~20%。

```python
"""
题型难度统计更新器（EMA 版本）。

每轮训练后调用，更新 difficulty_stats.json 中各 problem_type 的：
  - ema_success: 历史加权成功率
  - n_obs: 总观测次数
  - sampling_weight: 下一轮训练的采样权重

采样权重公式（来自 SPICE arXiv:2510.24684 方差奖励，高斯型）：
  w(p) = exp(-((p*(1-p) - 0.25)²) / (2*0.02))
  → p=0.5 时 w=1.0（最大采样），p=0或1 时 w→0.15（最小采样）
"""
import json, os, math
from collections import defaultdict

EMA_ALPHA = 0.3  # 平滑系数，0.3 表示当前轮占 30%

def compute_sampling_weight(ema_success: float, min_weight: float = 0.15) -> float:
    """
    方差校准的高斯采样权重。
    
    借鉴 SPICE 论文的 Gaussian variance reward（Eq.1）：
    越接近 p=0.5（一半对一半错），学习价值越高，采样权重越大。
    相比线性三角形公式，高斯形状梯度连续，无间断点，更适合数值优化。
    
    数值范例（按当前公式）：
      p=0.50 → weight=1.000（最大，最有学习价值）
      p=0.30 → weight≈0.961
      p=0.70 → weight≈0.961
      p=0.10 → weight≈0.527
      p=0.90 → weight≈0.527
    """
    variance = ema_success * (1 - ema_success)  # p*(1-p)，p=0.5时最大=0.25
    w = math.exp(-((variance - 0.25) ** 2) / (2 * 0.02))
    return max(min_weight, w)

def update_stats(val_outputs_dir: str, stats_path: str) -> dict:
    """读取 validation 输出，更新 EMA 成功率和采样权重。"""
    stats = json.load(open(stats_path)) if os.path.exists(stats_path) else {}

    type_results = defaultdict(list)
    for fname in sorted(os.listdir(val_outputs_dir)):
        if not fname.endswith(".json"): continue
        records = json.load(open(os.path.join(val_outputs_dir, fname)))
        for r in (records if isinstance(records, list) else []):
            pt = r.get("problem_type", "unknown")
            gp = r.get("reward", {}).get("grounded_proxy", 0.0)
            type_results[pt].append(float(gp) > 0.5)

    for pt, successes in type_results.items():
        if stats.get(pt, {}).get("excluded"):
            continue
        round_success = sum(successes) / len(successes) if successes else 0.5
        if pt not in stats:
            stats[pt] = {"ema_success": 0.5, "n_obs": 0, "formula_weight": 1.0, "sampling_weight": 1.0}
        old_ema = stats[pt]["ema_success"]
        new_ema = (1 - EMA_ALPHA) * old_ema + EMA_ALPHA * round_success
        n_obs   = stats[pt]["n_obs"] + len(successes)
        # n_obs < 20 时不降权，积累足够数据后再更新
        formula_weight = compute_sampling_weight(new_ema) if n_obs >= 20 else 1.0
        stats[pt] = {
            **stats[pt],
            "ema_success": new_ema,
            "n_obs": n_obs,
            "formula_weight": formula_weight,
            "sampling_weight": formula_weight,
        }

    with open(stats_path, "w") as f: json.dump(stats, f, indent=2)
    print(f"[DifficultyUpdater] Updated {len(stats)} problem types → {stats_path}")
    return stats


# ─────────────────────────────────────────────────────────────────
#  R1 补全：OC-Scorer 健康监控
#  将 Phase 0 的 Spearman 审计制度化为常态化每轮监控，
#  防止 OC-Scorer 自身随训练进行而被 reward hacking。
# ─────────────────────────────────────────────────────────────────

def check_oc_scorer_health(
    val_dir: str,
    alert_log_path: str = "analysis/scorer_health_alerts.json",
    spearman_threshold: float = 0.10,
    consecutive_fail_limit: int = 2,
) -> bool:
    """
    每轮训练后自动检查 OC-Scorer 与 grounded_proxy 的 Spearman 相关性。
    若相关性 < threshold，写入 alert_log 并打印警告。
    若连续 consecutive_fail_limit 轮失败，建议暂停训练并重新审视 OC-Scorer prompt。

    返回 True 表示 Scorer 健康，False 表示需要人工介入。

    调用位置：curriculum_trainer.py 的 run_round() 末尾（难度更新之后）。
    """
    import glob
    from scipy.stats import spearmanr

    oc_scores, gp_scores = [], []
    for fname in sorted(glob.glob(os.path.join(val_dir, "*.json"))):
        records = json.load(open(fname))
        for r in (records if isinstance(records, list) else []):
            reward = r.get("reward", {})
            if "scorer" in reward and "grounded_proxy" in reward:
                oc_scores.append(float(reward["scorer"]))
                gp_scores.append(float(reward["grounded_proxy"]))

    if len(oc_scores) < 50:
        print(f"[ScorerHealth] Too few samples ({len(oc_scores)}), skipping health check")
        return True

    rho, _ = spearmanr(oc_scores, gp_scores)
    is_healthy = rho >= spearman_threshold
    status = "✅ healthy" if is_healthy else "⚠️  ALERT"
    print(f"[ScorerHealth] Spearman(oc_scorer, grounded_proxy) = {rho:.3f}  {status}")

    # 写入 alert log（追加模式）
    os.makedirs(os.path.dirname(alert_log_path), exist_ok=True)
    alerts = json.load(open(alert_log_path)) if os.path.exists(alert_log_path) else []
    alerts.append({"spearman": round(rho, 4), "n": len(oc_scores), "healthy": is_healthy})
    json.dump(alerts, open(alert_log_path, "w"), indent=2)

    # 连续失败检查
    recent = alerts[-consecutive_fail_limit:]
    if len(recent) == consecutive_fail_limit and all(not a["healthy"] for a in recent):
        print(
            f"[ScorerHealth] ❌ OC-Scorer has failed health check {consecutive_fail_limit} "
            f"consecutive rounds. Recommend pausing training and reviewing OC-Scorer prompt."
        )

    return is_healthy


# ─────────────────────────────────────────────────────────────────
#  R8 补全：per-task-type reward 归一化
#  消除多任务 reward scale 不均衡问题（选择题 {0,1} vs 软分题 {0,0.5,0.8,1}）
# ─────────────────────────────────────────────────────────────────

def normalize_grounded_proxy_per_type(
    gp: float,
    problem_type: str,
    stats: dict,
) -> float:
    """
    用历史 EMA 统计做 per-type z-score 近似归一化，压回 [0,1]。
    stats 里需要存储 {"gp_mean": ..., "gp_std": ...} 按 problem_type 索引。

    调用位置：rollout_async() 中计算 final_reward 前，或在 compute_hybrid_reward 内。
    stats 的 gp_mean/gp_std 由本文件的 update_stats() 每轮同步更新。
    """
    type_stats = stats.get(problem_type, {})
    mean = type_stats.get("gp_mean", 0.5)
    std  = type_stats.get("gp_std",  0.25)
    if std < 1e-6:
        return gp   # 方差极小（如全对/全错）时不归一化
    normalized = (gp - mean) / std * 0.25 + 0.5
    return max(0.0, min(1.0, normalized))

def update_stats_with_gp_distribution(stats: dict, type_results: dict) -> dict:
    """
    在 update_stats() 内调用，同步更新每种题型的 gp_mean 和 gp_std。
    type_results: {problem_type: [gp_value, ...]}
    """
    for pt, gp_values in type_results.items():
        if not gp_values or stats.get(pt, {}).get("excluded"):
            continue
        import statistics
        mean = statistics.mean(gp_values)
        std  = statistics.stdev(gp_values) if len(gp_values) > 1 else 0.25
        stats.setdefault(pt, {}).update({"gp_mean": round(mean, 4), "gp_std": round(std, 4)})
    return stats
```

#### 新建文件：`curriculum_trainer.py`（外环主控）

> **这个文件是什么**：整个外环课程训练的主控脚本，负责按轮次（round）循环执行：读取难度权重 → 生成重采样后的 train dataset 文件 → 调用 1 轮训练 → 运行离线评估 → 更新难度权重 → 进入下一轮。
>
> **目的**：把"每轮 1 epoch + 动态重采样"这个外环逻辑封装成一个统一的入口，避免手动反复执行多个脚本。课程学习必须放在外环（而不是塞进单个 rollout），因为当前数据集在 `trainer.fit()` 前就已生成完毕，rollout 期间无法动态改变采样分布。
>
> **工程前提**：`train_strategy_generation.py` 需要先支持 `--train-dataset-json`。没有这个入口，外环只能“算出权重”，不能把重采样结果喂回训练。
>
> **预期效果**：4 轮课程训练后，能力边界题型（0.3 ≤ p ≤ 0.7）的采样占比 > 50%；OOD correctness 不低于无课程版本；如果课程导致 OOD 下滑 > 3%，自动回退到上一轮 stats。

```python
"""
外环课程训练主控器。

每 round 流程：
  1. 读 difficulty_stats.json → 按 sampling_weight 重采样 dataset
  2. 写出 round_train.jsonl
  3. 调用 train_strategy_generation.py --train-dataset-json round_train.jsonl
  4. 调用 scorer_correctness_auditor.py（离线 audit）
  5. 调用 difficulty_stats_updater.py（更新难度权重）
  6. 可选：调用 preference_pair_miner.py + winner_strategy_distiller.py
  7. 进入下一 round

Usage:
  python curriculum_trainer.py \
      --curriculum-rounds 4 \
      --base-dataset-path data/strategy_gen_train.jsonl \
      --round-sample-size 5000 \
      --difficulty-stats-path analysis/difficulty_stats.json \
      --checkpoint-dir checkpoints_curriculum/
"""
import argparse, json, os, shutil, subprocess, random

def weighted_resample(stats: dict, base_dataset: list, target_n: int) -> list:
    """按 sampling_weight 加权采样 target_n 条，实现课程偏向。"""
    filtered = [
        d for d in base_dataset
        if not stats.get(d["problem_type"], {}).get("excluded", False)
    ]
    weights = [stats.get(d["problem_type"], {}).get("sampling_weight", 1.0)
               for d in filtered]
    total = sum(weights)
    probs = [w / total for w in weights]
    indices = random.choices(range(len(filtered)), weights=probs, k=target_n)
    return [filtered[i] for i in indices]

def find_last_completed_round(checkpoint_dir: str) -> int:
    """扫描 checkpoint_dir，返回已完成的最后一轮 round_id（-1 表示从头开始）。"""
    completed = [
        int(d.split("_")[1])
        for d in os.listdir(checkpoint_dir)
        if d.startswith("round_") and
           os.path.exists(os.path.join(checkpoint_dir, d, "training_complete.flag"))
    ]
    return max(completed) if completed else -1

def _maybe_rollback_on_ood_regression(
    round_id: int, args: argparse.Namespace, snapshot_path: str,
    ood_drop_threshold: float = 0.03,
):
    """若当前轮 OOD correctness 比上一轮下降超过阈值，回退 stats 快照。"""
    cur_report  = f"analysis/round_{round_id}/audit_report.json"
    prev_report = f"analysis/round_{round_id - 1}/audit_report.json"
    if round_id == 0 or not os.path.exists(cur_report) or not os.path.exists(prev_report):
        return
    cur_ood  = json.load(open(cur_report)).get("ood_correctness", None)
    prev_ood = json.load(open(prev_report)).get("ood_correctness", None)
    if cur_ood is not None and prev_ood is not None:
        if prev_ood - cur_ood > ood_drop_threshold:
            print(f"[Round {round_id}] OOD regression detected "
                  f"({prev_ood:.3f} → {cur_ood:.3f}), rolling back difficulty_stats")
            shutil.copy(snapshot_path, args.difficulty_stats_path)

def run_round(round_id: int, args: argparse.Namespace):
    print(f"\n{'='*60}\n  CURRICULUM ROUND {round_id+1}/{args.curriculum_rounds}\n{'='*60}")

    # ── 1. 读取基础数据集 ───────────────────────────────────────────
    base_dataset = []
    with open(args.base_dataset_path) as f:
        for line in f:
            line = line.strip()
            if line:
                base_dataset.append(json.loads(line))

    # ── 2. 按 difficulty_stats 重采样 ───────────────────────────────
    stats = json.load(open(args.difficulty_stats_path))
    sampled = weighted_resample(stats, base_dataset, args.round_sample_size)

    round_dir = os.path.join(args.checkpoint_dir, f"round_{round_id}")
    os.makedirs(round_dir, exist_ok=True)
    round_path = os.path.join(round_dir, "round_train.jsonl")
    with open(round_path, "w") as f:
        for d in sampled:
            f.write(json.dumps(d, ensure_ascii=False) + "\n")
    print(f"[Round {round_id}] Resampled {len(sampled)} samples → {round_path}")

    # ── 3. 保存 stats 快照（崩溃恢复用）──────────────────────────────
    snapshot_path = os.path.join(round_dir, "difficulty_stats_snapshot.json")
    shutil.copy(args.difficulty_stats_path, snapshot_path)

    # ── 4. 调用训练（捕获失败，不污染 stats）──────────────────────────
    train_ret = subprocess.run([
        "python3", "examples/strategy_extraction/train_strategy_generation.py",
        "--train-dataset-json", round_path,
        "--reward-mode", "hybrid_grounded",
        "--grounded-proxy-weight", "0.5",
        "--scorer-weight", "0.4",
        "--grounded-proxy-k", "4",
        "--checkpoint-dir", os.path.join(round_dir, "checkpoints"),
    ], check=False)

    if train_ret.returncode != 0:
        print(f"[Round {round_id}] ⚠️  Training failed (exit {train_ret.returncode}), "
              f"restoring stats snapshot and skipping this round")
        shutil.copy(snapshot_path, args.difficulty_stats_path)
        return

    # 写完成标记（用于 find_last_completed_round 断点续跑）
    open(os.path.join(round_dir, "training_complete.flag"), "w").close()

    # ── 5. 离线审计 ─────────────────────────────────────────────────
    val_dir = os.path.join(round_dir, "checkpoints", "validation_outputs")
    audit_out = f"analysis/round_{round_id}"
    subprocess.run([
        "python3", "analysis/scorer_correctness_auditor.py",
        "--val-dir", val_dir,
        "--output-dir", audit_out,
    ], check=False)

    # ── 6. 更新难度权重 ──────────────────────────────────────────────
    subprocess.run([
        "python3", "analysis/difficulty_stats_updater.py",
        "--val-dir", val_dir,
        "--stats-path", args.difficulty_stats_path,
    ], check=False)

    # ── 7. OOD 回退保护 ──────────────────────────────────────────────
    _maybe_rollback_on_ood_regression(round_id, args, snapshot_path)

    # ── 8. 可选：挖掘 preference pairs ──────────────────────────────
    traces_path = os.path.join(round_dir, "checkpoints", "rollout_traces.jsonl")
    if os.path.exists(traces_path) and args.run_preference_mining:
        pairs_path = f"analysis/round_{round_id}/preference_pairs.jsonl"
        subprocess.run([
            "python3", "analysis/preference_pair_miner.py",
            "--traces-path", traces_path,
            "--output-path", pairs_path,
        ], check=False)

    print(f"[Round {round_id}] ✅ Completed")

    parser.add_argument("--curriculum-rounds",    type=int,   default=4)

                        help="每轮训练后自动挖掘 preference pairs")
    parser.add_argument("--resume",               action="store_true",
                        help="从最后一个完成的 round 续跑")
    args = parser.parse_args()

    os.makedirs(args.checkpoint_dir, exist_ok=True)
    start_round = find_last_completed_round(args.checkpoint_dir) + 1 if args.resume else 0
    if start_round > 0:
        print(f"[Resume] Resuming from round {start_round}")

    for r in range(start_round, args.curriculum_rounds):
        run_round(r, args)

    print(f"\n✅ All {args.curriculum_rounds} curriculum rounds completed.")
```

### 支线 A：策略选择原则 SFT 数据（借鉴 Early Experience）

**触发条件**：Phase 3 产出 preference_pairs，且 margin ≥ 0.30 的对数 > 200

#### 新建文件：`analysis/build_self_reflection_sft_data.py`

> **这个文件是什么**：给定 winner/loser 策略对，构造 Prompt 让 GPT-4o 或 Qwen3-8B 生成一段"为什么 winner 策略比 loser 策略更好"的自然语言反思，把这些反思数据存成 SFT 训练样本。
>
> **目的**：让策略生成器不只是"被好策略训练"（RSFT），还能理解"好在哪里"（SR 反思）。这类似于让学生不只是模仿好答案，还要写总结"这道题好答案好在哪"——提升元学习（meta-learning）能力。
>
> **预期效果**：SR 预热后，RL 阶段的策略质量初始化更高，Scorer 分数更稳定，减少 RL 训练初期的波动。这个数据只进 SFT，不污染在线 RL 信号。

```python
"""
策略选择自我反思 SFT 数据构建器。
借鉴：[2510.08558] Agent Learning via Early Experience，Self-Reflection 机制。

对比 winner/loser 策略，让 LLM 生成"为什么 winner 更好"的反思文本，
作为策略生成器的 SFT 预热数据。
"""
SR_PROMPT = """
You are given few-shot examples and two problem-solving strategies extracted from them.

Few-shot examples:
{examples_text}

Strategy A (verified effectiveness score: {proxy_a:.2f}):
{strategy_a}

Strategy B (verified effectiveness score: {proxy_b:.2f}):
{strategy_b}

Strategy A achieves better results on this problem type.
In 3-5 sentences, explain:
1. What patterns in the examples does Strategy A capture that B misses?
2. Why is Strategy A more generalizable across similar problems?
3. What specific scenario would Strategy B fail in?

Write your reflection directly, no headings or meta-commentary.
"""

def build_sr_samples(preference_pairs_path: str, output_path: str,
                     min_margin: float = 0.30) -> list:
    import json, os
    pairs = [json.loads(l) for l in open(preference_pairs_path)
             if json.loads(l)["margin"] >= min_margin]

    samples = [{"prompt": SR_PROMPT.format(
        examples_text=p["fewshot_examples_text"],
        proxy_a=p["winner_grounded_proxy"],
        strategy_a=p["winner_strategy"],
        proxy_b=p["loser_grounded_proxy"],
        strategy_b=p["loser_strategy"],
    ), "sample_key": p["sample_key"]} for p in pairs]

    # 调用外部 LLM 批量生成 reflection（GPT-4o 或 Qwen3-8B）
    # 生成完成后存入 output_path 供 SFT 训练
    os.makedirs(os.path.dirname(output_path), exist_ok=True)
    print(f"[SR Builder] {len(samples)} prompts prepared → call LLM to generate reflections")
    return samples
```

### 支线 B：步骤级因果归因（借鉴 SCO-PAL + AgentEvolver）

**触发条件**：Phase 1 parse rate > 95%，策略步骤可稳定解析

> **这是什么**：对一条结构化策略（有 STEPS 1~K），逐步截断到前 k 步，每次用 Answer Model 采样 M 次测试正确率 p(k)，以 `step_credit(k) = p(k) - p(k-1)` 作为每步的"边际贡献"。
>
> **目的**：找出策略中哪些步骤对答题成功贡献最大，用于：（1）指导 Scorer prompt 的更新；（2）验证 strategy_structured_schema.toml 引导出的步骤是否真的有因果效力；（3）为未来步骤级奖励提供数据支撑。
>
> **预期效果**：能找出"Step 1 几乎没贡献，Step 3 是关键"这类规律，指导策略提取 Prompt 的迭代。

```python
"""
Monte Carlo 步骤级因果归因。
来源：SCO-PAL [2510.16761] r(s_i, a_i) = Nwin(k)/Nall
      AgentEvolver [2511.10395] Self-Attributing: Good/Bad step labeling

离线计算，不在 rollout 里做，避免推理成本翻倍。
"""
def estimate_step_credits(
    steps: list[str],          # 来自 StrategyIR.steps
    problem: str,
    answer_model_fn,           # callable(partial_strategy, problem) -> bool
    M: int = 5,                # 每个截断点采样次数
) -> list[float]:
    """返回每步的边际正确率贡献（sum ≈ 完整策略的正确率）。"""
    credits, prev_p = [], 0.0
    for k in range(1, len(steps) + 1):
        partial = "\n".join(f"{i+1}. {s}" for i, s in enumerate(steps[:k]))
        p_k = sum(answer_model_fn(partial, problem) for _ in range(M)) / M
        credits.append(round(p_k - prev_p, 4))
        prev_p = p_k
    return credits
```

### 支线 C：经验模型加速 Rollout（借鉴 DreamGym）

**触发条件**：主线稳定，需要扩大 rollout 数量时

> **这是什么**：用已有 rollout traces 中的 (strategy_text, problem_type, problem, grounded_proxy) 数据，训练一个轻量回归模型（Ridge Regression 或 3层 MLP），直接预测"给定这条策略，Answer Model 大概能得多少 grounded_proxy"。

### 8.1 固定 5 个 Baseline（用名称而非版本号区分）

| **Baseline-Structured** | structured schema prompt + scorer-only | R = 0.1·fmt + 0.9·scorer | 验证格式升级的纯收益 |

```
  ✗ 任一不满足 → 先修策略提取/判分路由/采样设置，不启动完整训练

Phase 4（Curriculum Gate）：
  ✓ 边界难度题型（0.3 ≤ p ≤ 0.7）采样占比 > 50%
  ✓ OOD 不低于无课程版本
  ✗ OOD 下滑 > 3% → 回退上一 round stats
```

#### Task 1.4 ｜ 改造 `strategy_generation_agent.py` rollout 流程

**文件**：`examples/strategy_extraction/strategy_generation_agent.py`  
**现状**：`rollout_async()` 的 Step 3 只调用一次 Answer Model，Step 4 直接算 `scorer_reward × 0.9`

**实施步骤**：

**步骤 A：新增 `_score_strategy_raw_untraced()` 方法**（Task I3，参见 Section 1.4 补全提示）

**步骤 B：改造 `rollout_async()` Step 3 为 K=4 并发调用**：
```python
# 旧（仅一次调用）:
answer_raw = await self._generate_answer_untraced(...)

# 新（K次并发，答案列表）:
async def _answer_once(bound_strategy: str) -> str:
    return await self._generate_answer_untraced(..., strategy=bound_strategy, ...)
eval_result = await evaluate_strategy_k_samples(
    strategy=strategy,
    targets=task.get("ground_truths", [task["ground_truth"]]),
    task_meta=task.get("task_meta", {}),
    answer_fn=_answer_once,
    k=self.grounded_proxy_k,
)
rep = select_representative_answer(eval_result["answer_raw_list"], eval_result["router_scores"])
```

**步骤 C：改造 Step 4 Scorer 调用为 OC prompt**：
```python
# 旧: raw_scorer = await self._score_strategy_untraced(strategy, examples_text, problem)
# 新: 使用代表答案 + 标签
raw_scorer_json = await self._score_strategy_raw_untraced(
    strategy, examples_text, problem,
    answer=rep["representative_answer"],
    correctness_label=rep["representative_label"],
)
oc_scorer = parse_oc_scorer_response(raw_scorer_json)
```

**步骤 D：根据 `reward_mode` 分支计算 final_reward**：
```python
if self.reward_mode == "hybrid_grounded":
    final_reward = compute_hybrid_reward(
        format_r=format_reward, oc_scorer_r=oc_scorer,
        grounded_proxy=eval_result["grounded_proxy"],
        format_weight=self.format_weight,
        scorer_weight=self.scorer_weight,
        proxy_weight=self.proxy_weight,
    )
else:  # scorer_only（旧模式，向后兼容）
    final_reward = self.reward_config.compute_final_reward(
        format_reward, oc_scorer, 0.0,
        self.format_weight, self.scorer_weight, 0.0,
    )
```

**步骤 E：扩展 `reward_details` dict**，新增字段（参见 Section 1.4 补全内容，含 `grounded_proxy`、`soft_correctness_mean`、`answer_model_version`、`used_soft_fallback`）

**步骤 F（R3 软 fallback 落地）**：  
> ⚠️ **Issue 1 解决方案**：当前 agent 是逐 rollout 发送标量 reward，组级别 all-zero 检测需在 batch 层面处理。实际可行的方案是：
>
> 在 `rollout()` 方法（同步批量方法）而非 `rollout_async()`（单条方法）中，待一批 N 条 rollout 完成后，对同一 `sample_key` 的 rollout 分组，检查组内所有 `grounded_proxy` 是否全为 0；若是，将这批 rollout 的 `final_reward` 替换为 `soft_correctness_mean × 0.3`，并在 `reward_details` 中记录 `"used_soft_fallback": True`。
>
> 如果 `rollout()` 不可扩展（VERL 框架限制），则退化为 **per-rollout soft fallback**：直接在 `rollout_async()` 中，若 `grounded_proxy == 0.0` 则用 `soft_correctness_mean × 0.3` 替代，不等待组级判断。这是低成本次优方案，仍优于完全不使用软信号。
>
> 在 `__init__()` 新增参数：`self.soft_fallback_scale: float = config.get("soft_fallback_scale", 0.3)`

**步骤 G：`__init__()` 新增参数**：
```python
self.reward_mode       = config.get("reward_mode",          "scorer_only")
self.proxy_weight      = config.get("grounded_proxy_weight", 0.5)
self.grounded_proxy_k  = config.get("grounded_proxy_k",      4)
self.answer_model_version = config.get("answer_model_version", "unknown")
```

- `reward_details["scorer"]` 反映 OC-Scorer 的连续分数（不再是三档离散）
- `reward_details["used_soft_fallback"]` 正确标记降级样本

**迭代方案**：若 K=4 并发导致 Answer Model timeout（> 30s），先临时降到 K=2，在吞吐基准测试（Task 2.1）通过后再恢复 K=4。
